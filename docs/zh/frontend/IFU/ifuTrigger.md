# IFU 子模块 Trigger

## 功能描述

### 作用定位
Trigger 的主体实现在后端，但部分触发判断需要在指令执行前完成，因此需要前端 IFU 配合。以下内容从 IFU 的角度说明 Trigger 的处理逻辑。

触发器在非调试模式下工作；调试模式可建立一系列触发器。当同时触发进入调试模式和断点异常时，优先进入调试模式，且推荐同时生成断点异常。触发器可用于本地调试：无需依赖外部调试器（JTAG），而是通过异常机制进行调试。触发器通常由用户态或监督态设置，也支持在机器态设置；在 M 模式下，开发人员需明确其配置的影响。

### IFU 侧的处理方式
触发寄存器仅可在机器模式和调试模式下设置。IFU 中的 Trigger 逻辑用于配合后端 Trigger 模块，目前仅涉及对送往 IBuffer 的 PC 进行比较，尚不支持使用预译码或指令数据。

IFU 的 Trigger 包含 4 个由后端设置的 `tdata` 寄存器。逻辑会遍历送往 IBuffer 的全部 PC，并按 `matchType` 的匹配规则进行匹配。匹配后，还需确认 `tdata.select` 指示地址匹配目标且当前处于非调试模式，才能确定命中。

即使命中，仍需综合 `tdata.timing`、`tdata.chain` 和 `tdata.action` 判断，分别对应触发时机、链式匹配和触发动作。

### 设计约束
IFU 中的触发标记仅表示“预触发”，并不代表一定会触发，因为被标记的指令不一定会执行。该机制用于尽早发现潜在触发条件，并在后端执行阶段进行最终确认。
