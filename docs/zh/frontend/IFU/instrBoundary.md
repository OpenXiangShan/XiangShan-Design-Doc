# IFU 子模块 instrBoundary

## 功能描述

### 功能概述
`instrBoundary` 主要用于确定一个预测块中所有指令的边界信息，包括：

- 每条指令的有效起始位置和结束位置；
- 每条指令是否为压缩指令（C 指令）；
- 每条指令相对于预测块首地址的偏移 `endOffset`；
- 每条指令的归属于预测1还是预测块2。

除了调试模式外，后端通常不会直接使用前端传递的 PC，而是根据 `isRvc`、`endOffset` 和预测块首地址重新计算该指令的 PC。这样做可以减少前端到后端传递的存储开销，并降低带宽压力。

### 指令边界确定方式
指令流在语义上以“指令”作为最小粒度，因此在复位或后端重定向后，首个预测块的起始地址一定落在某条指令的起点上。

根据 RISC-V 指令格式定义，指令开头的 2 bit 可用于区分指令类型：

- `2'b11` 表示 32 位 I 指令；
- 其他情况通常表示 16 位 C 指令。

因此，一旦当前预测块的第一条指令位置和类型被确定，后续指令的位置和类型就可以依次沿着指令流往后推导。

不过，这种逐条推导方式的缺点非常明显：

- 过程本质上是串行的；
- 需要按指令逐个传播状态；
- 会带来明显的时序压力，成为关键路径上的“杀手”。

### 实现思路：并行切分与选择
一个预测块的最大取指长度为 64 字节，且指令按 2 字节对齐，因此可将其划分为 32 个槽位。

设计中采用一种折中的并行方法：

1. 前半段（槽 0~15）的指令边界直接按指令流顺序推导；
2. 对后半段（槽 16~31）并行推导两种假设：假设槽 16 落在一条跨入的 32 位指令中间（即槽 15 起始的 RVI 指令覆盖到槽 16），或假设槽 16 本身是一条指令的起始位置；
3. 前半段推导完成后，根据槽 15 的实际结果（是否为 32 位指令的起始位置）从两种候选中选择正确的一组；
4. 最终将前、后两段结果拼接为完整的指令边界。

这样做的好处是：

- 槽 0~15 的推导与槽 16~31 的推导可以并行进行；
- 提高了组合逻辑的吞吐能力；
- 使时序压力明显低于完全串行的逐条推导。

理论上，可以在一次切分的基础上继续进行多次切分，从而进一步追求时序最优；但这样会带来额外代价：

- 局部布线复杂度上升；
- 切分次数越多，布线和选择逻辑越复杂；

因此，这不是一个“无偿优化”，而是需要在时序、面积和布线复杂度之间进行权衡，以达到工程上可接受的实现效果。
