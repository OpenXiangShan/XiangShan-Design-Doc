## Design Specifications

Matrix functional units read and write dimension state, check data types, and generate AMU control requests. The mx register file stores matrix dimensions; CUTE stores matrix data and performs multiply-accumulate operations.

Table: Matrix Functional Units

| Functional Unit  | Execution Resource | Function                                                   | FU Latency Configuration |
| ---------------- | ------------------ | ---------------------------------------------------------- | ------------------------ |
| MSetMtilexRiWmf  | Int MSET0          | Write mtilem/n/k from an integer or immediate              | CertainLatency(0)        |
| MSetMtilexRmfWmf | Mf MSET1           | Read mtilem/n/k and write integer rd                       | CertainLatency(0)        |
| Mcfg             | Int BJU3           | msetcfg, mgetcfg                                           | CertainLatency(0)        |
| Mma              | Mf MEX0            | Check mmacc parameters and generate requests               | CertainLatency(0)        |
| Marith           | Mf MEX1            | Generate mzero requests                                    | CertainLatency(0)        |
| Mrelease         | Int MRELEASE       | Generate release requests                                  | CertainLatency(0)        |
| MLSU             | Mem MLSU0          | Check addresses, permissions, and matrix memory parameters | UncertainLatency(3)      |

FU latency configuration controls scheduling and writeback in the control core. Requests generated by Mma, Marith, Mrelease, and MLSU wait in [AmuCtrlBuffer](../CtrlBlock/AMUCtrlBuffer.md) until ROB commit, then are delivered to CUTE to execute the corresponding tasks.

## Dimension Configuration

`msettilem/n/k` reads an integer register; immediate forms read the 10-bit unsigned value in instr[24:15]. The value is written unchanged to the corresponding physical mx entry. Mma and MLSU check the dimension upper bounds for each operation when using these values.

At decode, `csrr mtilem/n/k` becomes MSetMtilexRmfWmf, which reads the corresponding mx entry and writes the integer destination register. This path uses ordinary register dependencies, allowing dimension-setting instructions and their consumers to be scheduled out of order.

## Type Configuration

`msetcfg` checks type_code and table_sel; invalid values generate illegalInstr. A valid value is written back to ROB and committed through MCfgBuffer to [MCfgGen](../CtrlBlock/MCfgGen.md). `mgetcfg` returns the raw value captured at decode. The upper payload bits are preserved unchanged.

## Mma

Mma reads M, N, and K from mx and the three mcfg snapshots carried by the instruction, checks matrix register classes, type combinations, and dimensions, then constructs AmuMmaIO.

Table: Mma Legality Checks

| Check                    | Condition                                                   |
| ------------------------ | ----------------------------------------------------------- |
| Source matrix indices    | The 3-bit selectors ms1 and ms2 are 0–3                     |
| Destination matrix index | The 3-bit selector md is 4–7                                |
| Configuration entries    | All three mcfg entries use currently supported encodings    |
| Type combination         | MatrixIsaParams enables the corresponding A/B/C combination |
| M                        | M <= ROWNUM                                                 |
| N                        | N <= ROWNUM, and N <= ARLEN / C element bit width           |
| K                        | K <= TRLEN / A element bit width                            |

`ROWNUM=TLEN/TRLEN` and `ARLEN=ROWNUM×MELEN`. Dimension checks compare upper bounds; zero dimensions also satisfy these conditions. The illegal conditions are ORed into exceptionVec.illegalInstr.

CUTE's ADC and BDC share AB read ports, so the two sources must select different matrix registers. Mma's illegal-instruction check does not include the `ms1 != ms2` constraint; simultaneous reads of the same register trigger a CUTE port-conflict assertion. See [Matrix Registers](../../cute/MatrixReg.md) for the port organization.

AmuMmaIO contains md, ms1, ms2, M/N/K, three element types, isfp, rm, and sat. For a floating-point destination, rm comes from mfrm; otherwise, it comes from mxrm. sat comes from msaten. CUTE's compute datapath does not yet use rm or sat; see [Compute Datapath](../../cute/Compute.md) for the computation behavior.

## Marith

The valid Marith decode is `mzero`; its control information contains the destination matrix index and opType. The instruction has no mx dimension source and leaves mcfg unchanged. The Marith wrapper directly generates a zeroing request without register-class or type-combination checks.

## AMU Control Interface

Table: AmuCtrlIO

| Field      | Width                   | Description                                                       |
| ---------- | ----------------------- | ----------------------------------------------------------------- |
| op         | 2                       | 0=MMA, 1=MLS, 2=release, 3=arith                                  |
| data       | 150                     | Control parameters interpreted according to op, with zero padding |
| pc, coreid | Configuration-dependent | Present only when DiffTest is enabled                             |

With 9-bit dimension fields, the effective payload is 53 bits for MMA, 126 bits for MLS, and 13 bits for arith. A forward release request carries a log2Ceil(MsyncRegs)-bit index; the completion return interface carries an MsyncRegs-bit event vector.

See [MLSU](../../memblock/LSU/MLSU.md) for address translation and replay of matrix memory operations. CUTE handles data movement, task scheduling, and completion returns. The Fence implementation of matrix synchronization instructions is described in [IntFunctionUnit](./IntFunctionUnit.md#sec:matrix-sync).
